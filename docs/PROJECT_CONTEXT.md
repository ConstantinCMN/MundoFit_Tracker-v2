## What this product is

A mobile-first fitness tracker for Romanian, English, and Spanish speakers, covering the full fitness lifecycle: onboarding, workout planning and execution, body/measurement tracking, progress photos, and calorie/TDEE targets. Romanian is the primary market (default locale, default fallback).

## Non-obvious constraints to respect

- **All mutations go through Server Actions** returning a discriminated result union — no client-side direct Supabase writes, no `/api` round-trips for CRUD.
- **RLS is mandatory on every table** — owner-only policy is the default; any new table needs it from the first migration, not added later.
- **Weight is stored in kg, height in cm** — always. Unit conversion for imperial display happens only at the render layer, never in the database or in stored values.
- **i18n has no hardcoded copy** — every user-facing string goes through `messages/{ro,en,es}.json`; adding a string to one locale file without the other two is an incomplete change.
- **Session state uses absolute timestamps, not counters** — rest timers and elapsed time are derived from `Date.now() - startedAt`-style math so they self-correct after backgrounding/locking. Don't reintroduce decrementing-counter timers.
- **The `(session)` route group has no app shell on purpose** — it was split out specifically to remove accidental-exit paths (bottom nav, header back button) during an active workout. Don't add shared shell chrome back into it without reading `docs/qa/QA-01-Workout-Session-Audit.md` (C-03/C-04) first.
- **Exercise data ownership is being migrated** — new features that touch exercises should go through `data/exercises/` + `lib/exercises/`, not the old ad-hoc SQL seed migrations, to avoid diverging sources of truth.
